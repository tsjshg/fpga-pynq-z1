CPU からファブリックへ

小さな言語モデルを FPGA で速く動かす、という計画の現在地。 なぜ CPU では遅いのか、FPGA に移すと何が変わるのか、そして昨日それを初めて実測できた話。

2026-09-05 実測: PYNQ-Z1 (XC7Z020) 前段: ADRFT1 (MPFS095T)
続きがあります — 2026-09-08 追記

この資料は 2026-09-05 時点の理解です。3日後に測り直したところ、 ここに書いた 「PL は DDR の 74%」という読みが誤りだったことが分かりました。 74% という数字は DDR ではなく、その手前にあるもっと低い天井に張り付いていたものです。 結論の向きは変わらず、正しい値は 93.6%（1.97 GB/s）でした。

経緯を残すため、この資料はそのままにしてあります。何がどう変わったかは 「二つの天井」を参照してください。 本文中の該当箇所にも印を付けてあります。

この計画が目指していること

やりたいのは 「量子化した小さめの推論モデルを、FPGA で作った自作の演算回路で動かす」ことです。 GPU を買えば速いのは分かっていて、目的は自分で作ることのほうにあります。

ただ、ここまでの調査と実測で、当初の見立てが2回ひっくり返りました。 この資料は、いま何が分かっていて、次に何をするのかを図で共有するためのものです。

図1 — そもそもこのチップは何なのか

ここで大事なのは PL は最初から空っぽ だということです。DSP が 220 個載っていますが、 配線されていないので何もしません。何をする回路にするかを設計して、 ビットストリーム（回路の設計図を焼いたファイル）を作って流し込む、という手順を踏みます。

そして PL は勝手に DDR にアクセスできません。HP ポートという門が用意されていて、 そこを通る回路を自分で組んで初めてメモリに手が届きます。 ADRFT1 で行き詰まったのは、まさにこの門が塞がれていたからでした。

図2 — ファブリックの素材、LUT

実例として、昨日作った回路が実際にどれだけ使ったかを載せます。

資源使用全体割合役割
LUT4,36053,2008.2%制御・判定・アドレス計算など何でも
フリップフロップ6,199106,4005.8%値を1クロック覚える
Block RAM11.51408.2%まとまったデータの一時置き場
DSP02200.0%掛け算専用。今回は計算をしていないので未使用

DSP がちょうど 0 なのが分かりやすいと思います。あの回路はデータを運ぶだけで計算をしないので、 掛け算器を1個も使っていません。LUT は何でも屋、DSP は掛け算専門、という分業になっています。

掛け算は LUT でも作れますが、まともな幅の掛け算器を LUT で組むと数百個を食って遅くなります。 だから最初から焼き込んである専用回路が用意されている、というわけです。 このチップの DSP は 25ビット × 18ビットの符号付き掛け算器に 48 ビットの累算器が付いたもので、 INT8 を扱うにはかなり大きすぎます。

三値化すると DSP は要らなくなる

重みが +1 / 0 / −1 の三値になると、掛け算は「足す・何もしない・引く」の3択に変わります。 これは掛け算ではないので DSP ではなく LUT で作ります。 つまり三値の道に進むと、効いてくる予算は DSP の 220 個ではなく LUT の 53,200 個のほうです。 ざっと見積もって必要なのは 1,000〜1,500 個程度なので、LUT も余ります。 結局、足りないのは帯域だけ、という結論は変わりません。

図3 — なぜ「帯域」が壁になるのか

これが、この計画で最初にひっくり返った見立てです。 当初は「DSP が何百個も空いているから速くなるはず」と考えていました。実際には DSP はまったく足りていて、足りないのはメモリからの道幅のほうでした。

ここから出てくる結論

速くしたければ、重み1個あたりのバイト数を減らすのが一番効きます。 INT8（1バイト/重み）を三値化（約0.2バイト/重み）にすれば、同じ道幅で 5 倍の重みを流せます。 しかも三値なら掛け算が足し算・引き算で済むので、DSP すら要らなくなります。 BitNet b1.58 のようなモデルがこのボードに向いている理由がここにあります。

図4 — 昨日測ったのは「道をどれだけ使えるか」

「PL は同じことを 74% でやります」というのは、こういう意味でした。 同じメモリに対して、CPU は3割しか引き出せないが、PL は7割強を引き出せる。 ハードウェアで直接メモリを叩く回路のほうが、汎用 CPU よりずっと効率よくメモリを使えるということです。

2026-09-08 追記 — この節の 74% は誤りでした

1.54 GB/s という測定値そのものは正しいのですが、その解釈が違いました。 これは DDR の 2.1 GB/s に対する 74% ではなく、PL 側の「道幅」0.80 GB/s に対する 96%です。 AXI の経路は 64 ビット幅＝1クロックあたり 8 バイトしか運べないので、 100 MHz では 8 × 100,000,000 = 0.80 GB/s が上限になります。 読みの 0.77 も書きの 0.77 も、DDR ではなくこちらの天井に当たっていました。

読み専用の回路に作り替えて測り直した結果、PL が DDR から読み出せる本当の上限は 1.97 GB/s（DDR の 93.6%）でした。CPU の 33% に対して 2.8 倍で、 「PL のほうが DDR を引き出せる」という結論はむしろ強まっています。 ただし HP ポートを2本使うことが条件で、1本では 53.7% までしか届きません。 詳細は 「二つの天井」へ。

そして ADRFT1 では、CPU が 13% しか引き出せていませんでした。 あのボードで「遅い」と感じていたものの正体は、DDR の性能ではなく CPU がその性能を引き出せていなかったことだったわけです。 「ファブリックに移す価値がある」という仮説が実測で裏付けられたというのは、この差を指しています。

図5 — 昨日作った回路は「何もしない回路」

「何もしない回路をわざわざ作った」のには理由があります。 演算器を先に作り込んでしまうと、遅かったときに「回路が下手なのか、道が細いのか」が切り分けられません。 先に道の太さだけを確定させておけば、次に作る演算回路は「その道を食い切れるだけの規模」に設計すればよく、 過剰にも過少にもなりません。

転送後に元データと結果を1バイトずつ照合して完全一致を確認しています。 速いが壊れている、では意味がないので。

図6 — Mac 1台で回るようになった

これは地味に見えて、この計画で一番大きな成果かもしれません。 ADRFT1 では最後までこの一周が作れませんでした。 FPGA を書き換えるのに専用の器材（3万円以上）が必要で、しかも失敗すると復旧できない、という状態だったからです。 引き出しから出てきた PYNQ-Z1 では、初日にこれが回りました。

9/8

ちなみに、KV260（$199、性能は PYNQ-Z1 のおよそ 10 倍）への移行を検討していましたが、 PYNQ-Z1 が思ったより使えることが分かったので、判断は保留でよさそうです。 三値化した 135M クラスのモデルなら 512MB のメモリに収まるので、このボードで一度最後まで通せる可能性があります。

用語

PS
Processing System。チップに載っている完成品の CPU 側。Linux が動いている。
PL
Programmable Logic。空っぽの回路の土地。ここに自分の回路を建てる。「ファブリック」とほぼ同義。
ファブリック
PL の中身、書き換え可能な回路の海。布地（fabric）に喩えた呼び方。
ビットストリーム
回路の設計図をチップに流し込める形式にしたファイル（.bit）。これを読み込ませると PL がその回路になる。
DSP
ファブリックに埋め込まれている掛け算専用の小さな回路。このチップには 220 個ある。
HP ポート
High Performance port。PL から DDR メモリへ行くための門。これを通る回路を作らないと PL はメモリに触れない。
AXI
チップ内部の部品どうしをつなぐ規格。道路の規格のようなもの。
DMA
Direct Memory Access。CPU を介さずにメモリとデータをやりとりする運搬係の回路。
帯域
1秒間に運べるバイト数。この計画では一貫してこれが速度を決めている。
量子化
モデルの重みを粗い数値で表して小さくすること。INT8 は1バイト、三値は約0.2バイト。
